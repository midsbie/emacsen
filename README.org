#+TITLE: Emacsen

Build Emacs recipes into Docker images. Install an image's Emacs on the host, or run it in isolation for compatibility testing.

* Requirements

- Modern Linux, Docker Engine 25+ with BuildKit, access to the daemon.
- Bash 5, Git, curl, GNU coreutils and findutils, util-linux =flock=.
- =install=: a rootful daemon and an image whose distribution and release match the host. =docker= group membership is root-equivalent.

#+begin_src sh
git clone https://github.com/midsbie/emacsen.git
cd emacsen
./emacsen --help
#+end_src

* Recipes and builders

=recipes/NAME/recipe= defines target =NAME=: a source and a builder under =builders/=. Builder names are not targets.

| Recipe | Source              | Builder      | Host installation |
|--------+---------------------+--------------+-------------------|
| 26.3   | GNU release tarball | 26.3         | No                |
| 31.1   | GNU release tarball | ubuntu-26.04 | Ubuntu 26.04      |
| master | Locked Git commit   | ubuntu-26.04 | Ubuntu 26.04      |

Recipe, builder and lock metadata: =key=value= lines and =#= comments, no quoting or expansion. Keys are lowercase letters, digits and hyphens, starting with a letter. Duplicate, unknown and misplaced keys are refused.

- Recipe :: =source= and =builder= required; =version= optional, checked against the built Emacs. Source keys by kind:
- =tarball= :: =url=, =sha256=. Downloads are verified and cached at =.emacsen/sources/tarballs/SHA256=.
- =git= :: =url=, full =ref=. =recipes/NAME/lock= names the commit; a build requires a lock matching =ref=, fetches the commit at depth 1 into =.emacsen/sources/emacs.git= and exports it with =git archive=. Recipes name the GitHub mirror because savannah stalls on shallow fetches; the commit identifies the source.
- Builder :: =builders/NAME/{builder,Dockerfile,build.sh}=: build procedure, dependencies and configure options. =builder= accepts only =variants=, space-separated; without variants the file holds only comments. A builder used by one recipe is named for it; generalise it when a second recipe shares it.
- =26.3= :: Ubuntu 20.04 pinned by digest, =linux/amd64=, GCC 9. Terminal and batch only, with GnuTLS, XML and zlib. Prefix =/opt/emacs/26.3=; not host-installable. Docker's default seccomp profile blocks the ASLR change its dumper needs, so it builds with =CANNOT_DUMP=yes=: standard Lisp loads at every start and =dump-emacs= is unavailable.
- =ubuntu-26.04= :: Ubuntu 26.04, GCC 14, native compilation, tree-sitter, LTO; variants =x= and =server=. Prefix =/usr/local=; host-installable. Images keep the configured tree at =/build/emacs= and carry =install-info=. A generated =lisp/site-init.el= dumps =source-directory= as =/usr/local/share/emacs/VERSION/=, recorded as =source-directory:=; in the image its =src/= links to the tree's.

=update NAME= resolves a Git recipe's =ref= in its source repository and rewrites its lock; an annotated tag locks the commit it names. Builds never change the lock and refuse one naming anything but a commit.

#+begin_src sh
./emacsen update master
#+end_src

For local experiments, commit source changes on a branch and create =recipes/experiment/recipe=:

#+begin_example
source=git
url=/absolute/path/to/emacs
ref=refs/heads/experiment
builder=ubuntu-26.04
#+end_example

Local Git sources accept absolute paths or =file://= URLs; no push is required. Lock the branch before building:

#+begin_src sh
./emacsen update experiment
./emacsen build experiment
#+end_src

Only the locked commit enters the build. Keep it available for rebuilds with an empty source cache.

Concurrent Git builds serialize cache writes on =.emacsen/sources/emacs.git.lock=, then export their retained commits independently.

=emacs/= is an upstream submodule for analysis; builds do not require it.

* Build

#+begin_src sh
./emacsen build 26.3
#+end_src

A build is one =docker build --load= tagged =emacsen:NAME=, loaded into the local Docker image store. The builder directory is the context and the source archive enters as a named context, so recipe edits invalidate the compile layer only through its inputs: source, version and variant.

Variants, for builders that declare them:

- =x= :: Selected when =libx11-6= is installed on the host. X11, Xft, DBus, JPEG, PNG, RSVG, TIFF and XPM.
- =server= :: Selected otherwise. No X11, DBus, GConf, GSettings or sound.

=--variant x|server= overrides detection; refused for builders without variants.

Builds pass =--pull=. The Ubuntu 26.04 base floats and Ubuntu packages are unpinned; the 26.3 base is digest-pinned. A rebuild can differ and moves the tag, with previous image not retained.

Each build writes =.emacsen/builds/DIGEST.txt=, =DIGEST= being the image ID without =sha256:=. It holds =image-id:=, =image-tag:= and the image's =/usr/share/emacsen/build-info=: source, Emacs version, prefix, distribution, configure options, compiler, packages, and the builder's revision, dirty state and input hashes.

#+begin_src sh
./emacsen exec 26.3 -- cat /usr/share/emacsen/build-info
#+end_src

* Install

=install NAME= resolves =emacsen:NAME= to an image ID and runs Emacs's own =make install= from the image's retained build tree into the host's =/usr/local=. Importantly, **nothing compiles on the host and there is no host =make=, or privilege elevation**.

=make install= omits the C sources, so install then copies the tree's =src/*.c= and =src/*.h= to =share/emacs/VERSION/src=, replacing that version's previous copy. =find-function= and the help buffers' C source links reach them without the build tree, under =-Q= too.

Refused unless the daemon is rootful, the image carries =install-info=, and its =build-info= has =build-tree:=, =prefix: /usr/local=, =source-directory: /usr/local/share/emacs/VERSION/= and an =os-release:= equal to the host's =ID VERSION_ID=. The =26.3= recipe fails these. The container runs as root with no network, capabilities limited to CHOWN, DAC_OVERRIDE, FOWNER and FSETID, and privilege escalation disabled.

Rehearse first. =--into DIR= binds =DIR= at =/usr/local= in the container without changing the prefix; a chroot's =usr/local= also works. A staged tree is for inspection, not relocation.

#+begin_src sh
./emacsen build 31.1
stage=$(mktemp -d .emacsen/install-XXXXXXXX)
./emacsen install 31.1 --into "$stage/usr-local"
head -n 16 "$stage/usr-local/lib/emacsen/installed/31.1"
#+end_src

Then install the same image on the host; both runs report its ID on stderr:

#+begin_src sh
./emacsen install 31.1
#+end_src

Versions coexist in Emacs's version-named directories. The last install owns the shared files: =bin/emacs= links to its =emacs-VERSION=; =emacsclient=, =etags=, =ebrowse=, the manuals and the man pages are replaced. Each version's record, =/usr/local/lib/emacsen/installed/VERSION=, holds =image-id:=, =image-tag:= and the image's =build-info=. Neither files nor records depend on the image remaining available. A prefix takes one install at a time, from any checkout: a second is refused while the first holds =lib/emacsen/install.lock=.

* Run and exec

#+begin_src sh
./emacsen run 26.3 -- -Q --batch --eval '(princ emacs-version)'
./emacsen exec 26.3 -- sh -c 'printf "%s\n" "$PWD"; id'
#+end_src

=run NAME [--directory DIR] [-- EMACS-ARGS...]= starts the image's Emacs. =exec NAME [--directory DIR] -- COMMAND [ARGS...]= starts =COMMAND= from the image's =PATH=. Every command requires =NAME='s recipe in the checkout, even when its image exists.

- Image :: The image tagged =emacsen:NAME=; stderr reports its ID. Never built or pulled; a missing image fails with the build command to run.
- Project :: =DIR=, default the current directory, mounted at =/work=. Relative paths resolve against the current directory; symlinks resolve to the physical path, reported on stderr.
- Arguments :: Everything after =--= passes unchanged. =run= may omit =--= when there are no Emacs arguments; =exec= requires =COMMAND= after it. Pass =-Q= for compatibility checks.
- Filesystem :: Image, project and mounts beneath it are read-only. =HOME= (=/home/runtime=) and =TMPDIR= (=/tmp=) are tmpfs, discarded on exit, and allow execution for native compilation. No host configuration is mounted.
- User :: The caller's UID and GID. A root caller runs as =65534:65534= (=nobody=), which needs a world-readable project, as does rootless Docker's UID mapping.
- Isolation :: No network, all capabilities dropped, privilege escalation disabled.
- Streams :: Stdin is forwarded. When stdin and stdout are terminals, the container gets one with the caller's =TERM=, =--batch= included, and stdout and stderr share it; redirect or pipe to separate them.
- Exit status :: Emacs's or =COMMAND='s. emacsen errors exit 1 with the stderr prefix =emacsen:=. Docker failures exit 125 to 127: 126 for a non-executable =COMMAND=, 127 for one not found.

** Test a package

Run ERT from source, then from bytecode compiled by the image's Emacs: older Emacs cannot generally run newer bytecode. Load sources by absolute path; =-L /work= would prefer host-compiled =.elc= files. Keep newer Emacs source trees' =lisp/= off =load-path=, where they shadow the image's ERT and standard libraries.

The examples expect =my-package.el= and =test/my-package-tests.el= in =$package=, with no dependencies. Network is disabled: place dependencies in the project and add them to =load-path= in both passes.

#+begin_src sh
package=/path/to/my-package
./emacsen run 26.3 --directory "$package" -- -Q --batch \
  -l /work/my-package.el -l /work/test/my-package-tests.el \
  -f ert-run-tests-batch-and-exit
#+end_src

The project is read-only and each invocation is a new container, so one =exec= compiles copies in =/tmp=, then loads the bytecode in a second Emacs process. One process would hide code that works only because compilation evaluated it.

#+begin_src sh
./emacsen exec 26.3 --directory "$package" -- sh -c '
  cp -- my-package.el test/my-package-tests.el /tmp &&
  emacs -Q --batch -L /tmp -f batch-byte-compile /tmp/my-package.el /tmp/my-package-tests.el &&
  emacs -Q --batch -L /tmp -l /tmp/my-package-tests.elc -f ert-run-tests-batch-and-exit'
#+end_src

* Compatibility

- Base image :: Emacs links against the image's libraries, so an installable image must match the host's distribution and release; =install= refuses a mismatch. After a host release upgrade, target the new release in the builder and rebuild. Removed libraries stop old binaries: Ubuntu 26.04 replaces =libxml2.so.2= with =libxml2.so.16=.
- Native compilation :: The builder's compiler and =libgccjit-N-dev= must name one GCC version, currently 14. The host needs the matching =libgccjit= runtime.
- Tree-sitter :: The image's =libtree-sitter-dev=, 0.25 on Ubuntu 26.04, loads ABI 15 grammars. The host needs =libtree-sitter0.25=; the soname carries the minor version, so rebuild when a release upgrade changes it. Emacs 31+ installs grammars on demand into =~/.emacs.d/tree-sitter= (=treesit-auto-install-grammar=, =M-x treesit-install-language-grammar=), which needs Git and a C compiler on the host.

* Runtime dependencies

**Host** packages for an installed Emacs on Ubuntu 26.04, beyond the desktop or terminal libraries already present. Containers carry their own. As root:

=x=:

#+begin_src sh
apt install libgccjit0 liblcms2-2 libtree-sitter0.25
#+end_src

=server=:

#+begin_src sh
apt install libgccjit0 libgnutls30t64 libncurses6 libtree-sitter0.25 libxml2-16
#+end_src
